# Frontend — Overview

## Purpose

Internal staff dashboard for the Construction CRM. As of 2026-08-08, it has a real login flow, one section
wired to live data (leads), and a full visual redesign on Tailwind CSS + shadcn/ui — see
`.ai/FE/ARCHITECTURE.md` for what's real vs. mock and the styling architecture.

## Tech stack

| Layer | Technology | Version |
|---|---|---|
| Framework | Next.js (App Router) | ^15.1.0 |
| UI library | React / ReactDOM | ^19.0.0 |
| Language | TypeScript | ^5.7.2 |
| Styling | Tailwind CSS v4 | ^4.3.3 |
| Component system | shadcn/ui (`style: base-nova`), built on `@base-ui/react` (**not** Radix — see Open questions in `.ai/FE/ARCHITECTURE.md`) | shadcn CLI ^4.16.2, `@base-ui/react` ^1.7.0 |
| Icons | `lucide-react` | ^1.30.0 |
| Theming | `next-themes` (light/dark, class-based) | ^0.4.6 |
| Toasts | `sonner` | ^2.0.7 |
| Class utilities | `class-variance-authority`, `clsx`, `tailwind-merge` (shadcn's standard `cn()` helper stack) | — |
| Font | Geist (`next/font/google`) | — |
| Runtime | Node.js | 22 (per `Dockerfile`: `node:22-alpine`) |

No state management library, no HTTP client library (uses the native `fetch`), no test runner.

## Setup / run / build / test

```bash
cd frontend
cp .env.example .env.local
npm install

npm run dev       # next dev — http://localhost:3000
npm run build      # next build — type-checks and bundles
npm run start        # next start (serves the build output)
```

**Do not run `npm run build` while `npm run dev` is also running against the same `.next` directory** —
they share build artifacts in incompatible ways and the dev server will start serving `500`s
(`Cannot find module './NNN.js'`) until you stop it, `rm -rf .next`, and restart. Hit this exact issue twice
during development — always stop `dev` first if you need to run a production `build`.

You'll need the backend running too (`cd ../backend && npm run start:dev`) and at least one seeded user —
see `.ai/BE/features/user-accounts.md` for seeded credentials, or `.ai/PROJECT.md` for full local-setup
instructions covering both projects.

No `test` script is defined in `frontend/package.json` and no test files exist in the project.

## Adding a new shadcn component

```bash
npx shadcn@latest add <component-name>
```

Writes into `src/components/ui/`. Don't hand-edit those files beyond trivial tweaks — prefer re-running the
CLI (it won't overwrite by default; pass `--overwrite` if you want the latest version) so the component stays
in sync with the shadcn registry.
